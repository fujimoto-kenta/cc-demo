# デモ台本（発表者向け）

1時間の説明のうち、15分のライブデモ部分の台本です。説明資料本体は別途の「Claude Code 1時間ハンズオンガイド」を使います。

## ブランチの使い分け

| ブランチ | 中身 | 使いどころ |
| --- | --- | --- |
| `main` | 土台のみ（サーバー、Playwright、CLAUDE.md、Skill）。アプリ本体はない | ライブデモの出発点 |
| `demo/buggy-app` | 完成した TODO アプリ。バグを1つ含む | ライブ実装が想定とずれたときの退避先 |
| `demo/fixed` | バグ修正と回帰テスト入り | 模範解答。事前の動作確認用 |

仕込んであるバグ: 「未完了」「完了」フィルタ中に削除ボタンを押すと、**別の TODO が消える**。
原因: `public/app.js` が表示中リストの番号（index）で、全体の配列から `splice` している。

## 事前準備（前日まで）

- [ ] `docs/setup.md` の手順で環境構築し、`demo/fixed` で `npm run test:e2e` が通ることを確認
- [ ] デモ用に作業ディレクトリを別に用意する（本番で `main` を汚さないため）
  ```bash
  git clone https://github.com/fujimoto-kenta/cc-demo.git ~/cc-demo-live
  cd ~/cc-demo-live && npm ci
  git switch -c live-demo
  ```
- [ ] ターミナルの文字を大きくする（後ろの席から読めるサイズ）
- [ ] ブラウザは TODO アプリ用と GitHub 用のタブを開いておく
- [ ] `~/cc-demo-live` で `claude` を一度起動し、ログインと「このフォルダを信頼する」の承認を済ませておく
  （信頼していないフォルダでは `.claude/settings.json` の権限設定が無視され、確認ダイアログが増える）

## 本番の流れ（15分）

### 1. 計画を立てさせる（2分）

`claude` を起動し、Shift+Tab で **Plan mode** に切り替えてから入力:

```text
public/ に素のHTML/CSS/JavaScriptでTODOアプリを作りたい。
追加・完了チェック・削除・「すべて/未完了/完了」のフィルタ・localStorageへの保存に対応して。
まず計画を見せて
```

話すこと: CLAUDE.md を読んで「フレームワークを使わない」ルールを守った計画になっている点。

### 2. 実装させる（3分）

計画を承認。編集の確認画面で差分を見せながら許可していく。

話すこと: 1つずつ確認するのが基本。慣れたら Shift+Tab で「編集を自動承認」にできる。

### 3. 動かしてみる（2分）

```text
!npm start
```

または `サーバーを起動して` と頼む。ブラウザで http://localhost:3000 を操作して見せる。

### 4. コミット（1分）

```text
ここまでをコミットして
```

話すこと: 差分から自分でコミットメッセージを書く。

### 5. バグを見つける（2分）

> リハーサルでは、ライブで作ったアプリは ID で削除する正しい実装になり、バグは出なかった（実装は約1分）。
> そのため手順 4 のコミット後は、次のように用意済みのバグ入り版へ切り替えるのを基本とする。
>
> ```text
> !git switch demo/buggy-app
> ```
>
> 話すこと: 「実際の開発で、同僚が書いたコードにバグ報告が来た」という設定にする。

ブラウザで再現:

1. 「牛乳を買う」「本を読む」「散歩する」を追加
2. 「牛乳を買う」を完了にする
3. 「未完了」フィルタに切り替え
4. 「散歩する」の × を押す → **「本を読む」が消える**

### 6. バグを直させる（3分）

症状だけを伝える（原因は言わない）:

```text
「未完了」フィルタ中に「散歩する」を削除したら「本を読む」が消えた。
原因を特定して直して。再発しないようにE2Eテストも追加して
```

話すこと:

- コードを読んで原因（index のずれ）を説明してくれる
- 修正だけでなくテストを足し、`npm run test:e2e` で確かめるところまでやる
- `.claude/skills/run-e2e` の Skill が使われる様子が見えたら紹介する

### 7. レビューと PR（2分）

```text
/code-review
```

```text
ブランチを切ってコミットし、PRを作って
```

GitHub のタブで PR を開いて見せる。

## 時間が余ったら

- `Esc` を2回押して、修正前の状態に巻き戻せることを見せる
- `ダークモード切り替えボタンを追加して` などの機能追加
- `/init` で CLAUDE.md を再生成し、既存のものとの違いを見せる
- `/context` で文脈の使用量を見せ、`/clear` の大切さを話す

## デモ後の片付け

```bash
gh pr close <PR番号> --delete-branch   # デモで作った PR を閉じる
rm -rf ~/cc-demo-live
```
